# DSA helper toolkits (Python + Java)

> **Track:** M · **Status:** Done
> **Created:** 2026-09-17 · **Last updated:** 2026-09-17

## 1. Frame

**Problem**
The vault's `04-DSA-V2/00-index/py_dsa_utils.html` and `JavaDsaUtils.html` (copy-paste DSA helper
toolkits) only exist as standalone vault pages; the site's DSA section has just Cold recall.

**Outcome**
`/dsa/python-utils` and `/dsa/java-utils` show each toolkit in the site's M3 style: syntax sheet,
imports, helper cards (name, doc, highlighted code with copy), self-tests, a filter, section nav.

**Success criteria**
- SC1 Both pages render every section and helper from the vault file (15 sections; 61 / 76 helpers).
- SC2 Filter narrows helpers and syntax-sheet rows by name, doc or code; empty state when nothing matches.
- SC3 Section rail at `lg`+, Contents drawer below; `#s2-is_palindrome`-style deep links land below the app bar.
- SC4 Pages appear in the DSA nav/section page, and helpers appear in global search.
- SC5 Python ↔ Java twin links go to the other site page; no horizontal scroll at 360/390px.

**Non-goals**
- Editing the vault; serving the `.py` / `.java` source files (links dropped, text kept).

**Assumptions**
- Routes `/dsa/python-utils` and `/dsa/java-utils`, grouped as "Toolkits" under DSA.
- The vault's "How to use this page" callout is replaced by a short subtitle (it describes the vault page's own UI).

## 2. Discover

| Area | Finding | Impact on design |
| --- | --- | --- |
| Source | Both files are generated by `gen_java_html.py`-style scripts with identical markup: `section.sec > h2, p.lede, .sheet .row(.k,.v), .card(.card-head .tag + a.cname[id], p.doc, pre.code code)` | One structured extractor for both |
| Pattern to follow | `ColdRecallPage` (filter + JSON), `CaseStudyPage` (rail/drawer with `TableOfContents`) | Reuse both layouts |
| Reusable | `HtmlContent` gives hljs highlighting + copy buttons + `pre` styles; `useHashScroll` handles deep links | Code blocks render through `HtmlContent` |
| Risk | Some cards have no header (imports, Python self-tests) | `name`/`id` optional |

## 3. Architecture

**Chosen:** structured JSON per language (`dsa-utils-python.json`, `dsa-utils-java.json`) + one shared
`UtilsPage` component, with two tiny lazy route wrappers so each page only downloads its own JSON.
Rejected: cleaned article HTML via `HtmlContent` — can't filter per helper.

```ts
type UtilsHelper = { id?: string; name?: string; kind: string; doc?: string; code: string }
type UtilsSection = { id: string; title: string; lede?: string; sheet: { label: string; code: string }[]; helpers: UtilsHelper[] }
type UtilsToolkit = { lang: 'python' | 'java'; title: string; subtitle: string; meta: string; stats: { value: string; label: string }[]; sections: UtilsSection[] }
```

Manifest gains `dsaUtils: { lang, id, name, section }[]` for global search.
